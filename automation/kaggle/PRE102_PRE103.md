# NFSMW — PRE102/PRE103: acesso automatizado ao Google Drive

## Evidência PRE102 em 2026-11-04

O GitHub Actions disparou o notebook privado `juniklx/nfsmw-pre102-drive-probe` pelo Kaggle API, e o Kaggle reportou COMPLETE, mas a prova de acesso ao Drive falhou:

- Run GitHub: https://github.com/Juniklx/nfsmw-actions-teste/actions/runs/41800823947
- Relatório: `automation/kaggle/status/pre102_drive_probe.json`
- `fase_falha=KAGGLE_SECRETS`, `erro_tipo=ConnectionError`, `secret_label_indisponivel=GOOGLE_REFRESH_TOKEN`.
- Nenhum backup foi baixado/restaurado, nenhum APK foi compilado e nenhuma chave privada foi acessada.
- O comportamento é compatível com limitações do Kaggle Secrets quando o kernel é iniciado por `kaggle kernels push`. Não contornar com tokens no código ou na saída.

## Alternativa preparada: PRE103 — GitHub → Drive diretamente

O workflow **`.github/workflows/nfsmw-pre103-github-drive.yml`** usa o próprio GitHub Actions para consultar *somente metadados* do backup PRE99, autenticando com segredos do repositório. **Não foi iniciado**; requer configuração manual segura.

Adicionar em **Settings → Secrets and variables → Actions → New repository secret** do repositório privado, usando os valores de OAuth previamente mantidos em armazenamento privado:

- `GOOGLE_REFRESH_TOKEN`
- `GOOGLE_CLIENT_ID`
- `GOOGLE_CLIENT_SECRET`

Esses valores **nunca devem ser enviados ao ChatGPT, colocados nos arquivos, incluídos em commits, registrados em logs ou copiados para datasets**. O GitHub Actions Secret somente expõe o valor ao job autorizado, não ao texto do repositório. Guardar tokens de longa duração requer cuidado: limitar permissões do repo, evitar workflows não confiáveis, revogar em caso de exposição.

Uma vez configurados, publicar um JSON sob `automation/kaggle/github_drive_requests/` para disparar a PRE103. O resultado sanitizado aparecerá em `automation/kaggle/status/pre103_github_drive.json` sem qualquer valor de segredo.

O probe **não baixa o TAR**, mas compara MD5 e tamanho remotos com o manifesto e o SHA-256 *declarado*. A restauração real e SHA-256 do TAR continuam pendentes e exigem etapa posterior controlada.
